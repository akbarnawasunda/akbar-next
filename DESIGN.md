# Akbar Nawasunda — Public Website Design Direction


**Purpose:** creative direction, design intelligence, interaction language, and implementation guardrails for the public Akbar Nawasunda website.

**Important:** this is **not** a pixel-by-pixel layout to reproduce blindly. It is a design problem to solve.

The agent is expected to think like a senior art director, product designer, interaction designer, and front-end designer working together.

The final result must feel authored specifically for **Akbar Nawasunda**, not assembled from a generic creative-portfolio template.

 
# 1. PRIMARY OBJECTIVE

Create a distinctive official artist website for **Akbar Nawasunda**, a producer / remixer / DJ from Bandung Barat, Indonesia.

The website should feel like a **living nocturnal music archive**:


- dark

- cinematic

- restrained

- image-led

- editorial

- electronic

- tactile

- slightly strange

- human

- culturally grounded without becoming folkloric

- technically sophisticated without looking like a technology demo


The goal is not to make the website look "cool" at first glance.

The goal is to make the visitor recognize, after spending time with it:


**"This could only belong to Akbar Nawasunda."**


The design should feel intentional enough that removing the artist's name, logo, or content would **not** make the website interchangeable with 100 other electronic artists.

# 2. DESIGN INTELLIGENCE DIRECTIVE

Before changing layout or writing new components, independently analyze the identity problem.

Do not immediately code the first obvious solution.

First determine:


1. What makes Akbar Nawasunda visually distinguishable from other electronic artists?

2. How should the relationship between **DJ Akbar Remix** and **Akbar Nawasunda** be communicated?

3. How can Bandung Barat / Sunda influence the work without becoming literal cultural decoration, fake traditional motifs, or costume-like visual styling?

4. How should music, photography, typography, motion, interaction, and negative space behave as one system?

5. Which existing visual elements are genuinely ownable and which are generic?

6. Which parts of the current experience should be preserved?

7. Which parts should be simplified, removed, or radically restructured?

8. What should the website deliberately **not** do?

9. Where should visual density increase?

10. Where should the website become almost silent?


Do not assume that every recommendation in this document must remain unchanged.

You may:


- restructure sections

- combine sections

- remove unnecessary sections

- change hierarchy

- change the order of content

- simplify interactions

- refine colors

- reinterpret typography

- reinterpret the particle system


when doing so produces a stronger and more coherent result.

However, do not remove important brand assets or public functionality merely to make implementation easier.

# 3. THE CORE VISUAL IDEA

## Liquid Signal

The central visual language of the website should be **signal behaving like matter**.

The existing particle concept is important and must **not** be removed.

However, it should evolve beyond:


particles forming a static wordmark


or:


generic floating dots / WebGL wallpaper.


The preferred direction is a **liquid signal system**.

Imagine:


- magnetic dust

- suspended particles

- flowing matter

- pressure fields

- invisible currents

- particles with weight

- material that gathers, separates, drifts, and reforms


It may sometimes resemble liquid or ink suspended in water, but it should **not literally become a water-effect website**.

Avoid:


- obvious liquid blobs

- glossy glass

- watery gradients

- blue glassmorphism

- generic fluid simulation demos


The system should remain abstract.

# 4. SIGNATURE PARTICLE SYSTEM

## 4.1 The particle system is a brand asset

The particle field is not decoration.

It is part of the identity.

Treat it as a **persistent visual language** that can change behavior depending on context.

Possible states include:

### Drift

Slow ambient movement.

Particles gently orbit or travel through an invisible flow field.

The movement must be subtle enough that the user can read content normally.

### Magnetic response

When the pointer enters the field, nearby particles react.

The response should feel physical rather than artificial:


- attraction

- repulsion

- delayed movement

- local turbulence


Avoid exaggerated cursor trails.

### Flow

When the user moves through or interacts with a signal field, particles can create a short-lived directional stream.

### Gathering

Particles can temporarily converge into denser structures.

### Dissolution

The structure should be capable of breaking apart and returning to ambient movement.

### Formation

Under specific intentional interactions, the system may briefly form recognizable identity fragments such as:


- `AN`

- `AKBAR NAWASUNDA`

- `DJ AKBAR REMIX`


However:

**never treat the wordmark formation as the default effect.**

The viewer should occasionally discover that the identity emerges from the field, rather than being constantly shown a particle logo.

This makes the identity feel alive rather than promotional.

# 5. SIGNAL MEMORY

The website should behave like one connected system rather than a collection of disconnected page effects.

Where technically practical, preserve the visual logic of the signal between routes and major sections.

The signal can change character depending on context:


- Home: active, expressive

- Music: structured, rhythmic

- Visuals: sparse, observational

- Universe: archival, directional

- About: restrained

- EPK: minimal

- Privacy / document pages: almost silent

- JEDAG RUN: independent game world


Do not reset the visual language arbitrarily between every section.

The visitor should feel that the same underlying "matter" is traveling through the site.

# 6. DENSITY AND SILENCE

The website must alternate between **visual density and visual silence**.

Do not make every viewport simultaneously contain:


- particles

- grain

- glow

- large typography

- image overlays

- marquees

- animated borders

- rotating objects

- cursor effects

- multiple labels


Instead, deliberately create rhythm:


dense → quiet → dense → open → intimate → energetic → quiet


The website should have the pacing of music.

Some sections should almost feel still.

Silence is part of the design.

# 7. ANTI-AI-SLOP RULE

The website must not resemble a generic AI-generated "creative studio" or "electronic artist" site.

Avoid common AI-generated visual patterns such as:


- oversized fragmented headlines used everywhere

- excessive gradients

- purple/cyan neon

- glowing borders

- glassmorphism

- giant floating blobs

- random 3D objects

- generic chrome spheres

- fake sci-fi interfaces

- excessive rounded cards

- excessive pill-shaped UI

- dashboard layouts

- giant text centered in empty black space

- endless marquee text

- decorative particles without purpose

- long cursor trails

- random hover distortions

- excessive grain

- overuse of blur

- fake terminal aesthetics

- abstract "AI art" replacing real artist imagery

- excessive section labels

- repetitive reveal animations

- parallax for its own sake


A design element must have a reason tied to:


- the artist

- the content

- the interaction

- the music

- the navigation

- the identity


If the only reason is:


"it looks cool"


remove it or rethink it.

# 8. GENERIC ARTIST WEBSITE TEST

After implementation, perform this test:


If the Akbar Nawasunda name, logo, portrait, artwork, and artist-specific content were removed, would the website still look like it could belong to many unrelated electronic artists?


If the answer is **yes**, the design is not distinctive enough.

Rework the visual language.

The test should be performed against:


- hero

- typography

- interaction

- navigation

- music catalogue

- page transitions

- particle behavior

- cursor behavior


The goal is not novelty for novelty's sake.

The goal is **ownable coherence**.

# 16. NATIVE CURSOR + SIGNAL MARK

The pointer stays native. Do not replace, hide, decorate, or animate the
cursor — no custom dot, no companion, no trail, no magnetic pull, no
`cursor: none` anywhere.

The brand lives in the world of the website, not in a cursor following the
user's hand. Touch devices use the native pointer model.

The one ambient interaction element is the Signal Mark: a tiny steel-blue
signal trace (hairline + three segments + one slow point) in the bottom-right
safe area. It is atmosphere, not UI — a residual signal still moving through
the room while the page is idle.

Signal Mark rules:

- decorative only (`aria-hidden`); never semantic information
- extremely small footprint; easy to miss, hard to resent
- never covers text, buttons, artwork, the audio dock, footer, or game controls
  (it lifts above the dock and suppresses itself near the footer)
- motion lives in CSS keyframes only: no RAF loop, no pointer tracking,
  no canvas, no per-frame React state
- states: idle (barely breathing), scroll (brief stretch, direction-aware),
  audio playing (slightly more alive — amplitude breathes, never an equalizer),
  route transition (one short sweep), reduced motion (static mark)
- JEDAG RUN keeps its own visual language; the mark is absent there

# 37. MOTION LANGUAGE

Motion must feel physical and measured.

Allowed:


- route fade / lift

- short signal sweep

- image crop reveal

- subtle row interaction

- low-frequency mascot movement

- controlled particle motion

- restrained cursor reaction


Motion should generally live around:


- 160–220ms for local UI feedback

- ~420ms for simple route/image motion

- ~420–840ms for larger signal transitions


Do not make every section animate into existence.

The user should always be able to read immediately.

# 38. MOTION EXCEPTIONS

Permanent motion is reserved for:


- carefully controlled particle ambience

- optional mascot drift


Even these must:


- reduce on low-capability devices

- reduce or disable under `prefers-reduced-motion`


Do not run expensive canvas or RAF loops on static pages when they add no meaningful value.

# 39. PERFORMANCE

# 49. CREATIVE REVIEW BEFORE IMPLEMENTATION

### Restraint

### Originality

### Rhythm

Where are the dense and quiet moments?

### Photography

### Signal

# 50. REQUIRED DESIGN PRINCIPLE

## Design less. Mean more.

Whenever there is a choice between:


- more effects vs better composition

- more components vs better hierarchy

- more animation vs better pacing

- more decoration vs stronger identity


prefer the option with:

**more meaning and less noise.**

# 51. FINAL ART DIRECTION

The final website should feel like:


a dark room after the music has stopped, with residual signal still moving through the space.


The real artist imagery provides the human presence.

The typography provides the editorial structure.

The particle / liquid signal system provides the invisible physical language.

The mascot provides a small trace of personality.

The navigation provides precision.

The empty space provides confidence.

The motion provides rhythm.

Nothing should feel added merely because the implementation can support it.

# 52. IMPLEMENTATION PHASES

Do not jump directly from this document into arbitrary styling.

Work conceptually in these phases:

### Phase 1 — DISCOVER

Audit the existing public website, repository, assets, fonts, content, routes, and current interactions.

### Phase 2 — DEFINE

Determine:


- visual hierarchy

- identity principles

- page rhythm

- particle behavior

- typography roles

- image treatment

- navigation logic

- motion language


### Phase 3 — ART DIRECT

Create the strongest proposed visual system before implementing every page.

The design should establish:


- Home

- Music

- Visuals

- one document page

- one interactive state


as the core reference system.

### Phase 4 — IMPLEMENT

Apply the established system consistently across routes.

### Phase 5 — CRITIQUE

Actively search for:


- generic patterns

- unnecessary effects

- weak hierarchy

- repetitive cards

- accidental AI aesthetics

- accessibility failures

- mobile failures


### Phase 6 — REFINE

Simplify, improve, and polish.

Do not merely add more visual effects.
